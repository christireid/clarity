## Who I Am

I'm a senior engineer who has shipped AI products. I have high standards, deep technical expectations, and no patience for bullshit.

---

## Complaint 1: This Isn't an SDK

An SDK has:
- A published package with semver
- API documentation
- Type exports that are importable
- A stable public API surface
- Tests proving it works
- Examples showing integration

This has NONE of those. It's a Next.js app with components in it. Calling it an "SDK" is misleading.

---

## Complaint 2: The Export Story is Broken

`components/ai/index.ts` has ~40 commented-out exports because component files have naming collisions. This is a fundamental architecture failure. If you can't barrel-export your own library, it's not a library.

Examples of collisions:
- `StreamingText` exported from 3 different files
- `TypingIndicator` exported from 4 different files
- `FilePreview` exported from 3 different files
- `Queue` exported from 2 different files

This indicates the components were generated independently without any coordination of their public API.

---

## Complaint 3: Token Optimization is Vaporware

The `lib/token-optimization/` directory has 14 files including:
- SemanticCache, KVCache, SmartRouter, RAGSystem, MemoryManager, ChunkingStrategy

These are impressive-sounding module names. But:
1. None are integrated into the actual chat flow
2. The "test" is a console.log script
3. Token counting is approximated (no tiktoken integration on the client)
4. The RAG system uses TF-IDF — fine for a demo, useless at scale
5. No benchmarks comparing "optimized" vs "unoptimized" in real scenarios

---

## Complaint 4: No TypeScript Rigor

- `skipLibCheck: true` — So you're shipping types you haven't validated
- `@typescript-eslint/no-explicit-any: "warn"` — Not an error, just a warning
- Build explicitly skips type validation
- Unknown number of type errors lurking

For a project that claims to be "production-ready," this is unacceptable.

---

## Complaint 5: The Backend is a Toy

94 lines of FastAPI with:
- A root endpoint returning `{"message": "Hello World"}`
- A CRUD endpoint for "status checks" (unrelated to AI)
- A chat endpoint that delegates to a MockProvider
- No authentication
- No rate limiting
- No input validation (bare `except:` clause)
- CORS set to `*`
- Deprecated event handlers

The README calls this "A FastAPI service optimized for streaming." It's a boilerplate.

---

## Complaint 6: 84K Lines of What?

150+ component files totaling 84,093 lines. That's more code than many production applications. But:
- Every component is self-contained with its own mock data
- Components don't share state or context in meaningful ways
- There's massive duplication (multiple chat bubble implementations, multiple loading indicators, multiple status displays)
- Many components are nearly identical with slight styling variations

This looks like it was generated by prompting an AI with "create a component for X" 150 times without any architectural coordination.

## Complaint 8: Streaming Protocol is Non-Standard

The custom streaming protocol (`0:text`, `7:ui_json`, `5:error`) is undocumented outside the README. It's incompatible with:
- Server-Sent Events (SSE)
- Vercel AI SDK's streaming format
- OpenAI's streaming format
- Any standard

Custom protocols require custom clients. This creates lock-in with zero ecosystem.

---

## Complaint 9: Dependencies are Irresponsible

Backend `requirements.txt` has 127 packages including:
- `boto3` (AWS SDK) — never used
- `stripe` — never imported
- `pandas`, `numpy` — for a chat API?
- `pillow` — no image processing
- `huggingface_hub` — not used
- `google-genai`, `google-generativeai` — not used in providers

This is a security liability. Every unused dependency is unnecessary attack surface.
